TASK: JOINT PROMPT AND DECODING OPTIMIZATION FOR PNEUMONIAMNIST

Maximize accuracy of one fixed medical VLM on the frozen 100-image training subset.
The experiment selects either MedGemma 1.5 4B or MedGemma 27B and one original
resolution (28, 64, 128, or 224) before the run. These are eight separate conditions
implemented by this one task. The held-out 624-image test set is never used by
the evolutionary validator or for selecting the winning candidate.

Candidate interface
-------------------
Define a Python function with no arguments named entrypoint. Return a dictionary:

    def entrypoint():
        """Return the medical instruction and its decoder settings."""
        return {"prompt": PROMPT, "sampling": {"temperature": 0.3, "top_p": 0.9}}

You may mutate both the prompt string and the allowed sampling values:
- temperature: exactly 0, 0.1, 0.3, or 0.6.
- top_p: exactly 0.9 or 1.0.
- Zero temperature is canonical greedy decoding with top_p=1.
- top_k is disabled by default. Include it ONLY if the experiment explicitly
  states top_k support is enabled; its allowed values are -1, 20, and 50.
- In prompt-only control runs sampling must remain exactly temperature=0 and
  top_p=1, without a top_k restriction. Changes are rejected even at temperature=0.
- A legacy string return value is accepted with canonical greedy settings.

No other output fields or sampling keys are allowed. Do not import files, inspect
data or labels, change environment variables, use network calls, or change the
validator. The candidate describes one instruction and one decoder configuration
shared by every image; it does not classify images itself.

Fixed procedure and prediction format
------------------------------------
The evaluator converts each original image to RGB, resizes with bicubic sampling,
and pads with black to 896 by 896. Exactly one model request is made per image
per evaluation repeat. The response length is fixed at 256 tokens. Model identity,
data, evaluation repeat count, seed schedule, and networking are controlled by
the researcher, never by the candidate. Seeds are used only when the backend
has been explicitly configured to support them.

Ask the model to return a JSON object with these values:
  {"class_id": 0, "class_name": "normal"}
or
  {"class_id": 1, "class_name": "pneumonia"}

class_id must be an integer and class_name must match it. Invalid answers count
as wrong predictions. The exact name "normal (no pneumonia)" is normalized to
"normal" only for class_id=0. The evaluator tolerates surrounding text and repeated
identical complete JSON objects; conflicting complete answers or incomplete-only
JSON fail. An existing complete answer is retained if followed by an incomplete
tail; the tail is not repaired or treated as valid JSON.
JSON-only instructions are recommended.
Infrastructure errors abort the evaluation; they do not become poor fitness.

Fitness and search guidance
---------------------------
Fitness is accuracy across all training images. Repeated training passes, when
configured, are averaged without voting on model responses. parse_success_rate
is also reported. Sampling can increase evaluation noise and may not improve
accuracy; zero temperature remains an admissible solution.

Pneumonia cues include focal/lobar airspace opacity, patchy infiltrates,
consolidation, and air bronchograms. Confounders include atelectasis, edema,
rotation, exposure artifacts, and motion. These are prompts for a research
classification benchmark, not deployment instructions for clinical decisions.

The ten original starting prompts are preserved, initially with greedy decoding.
The joint candidate is saved as JSON so that final evaluation applies the same
prompt, sampling parameters, preprocessing, output parser, and scoring rules.
